# V0.5.5 | 知识驱动决策与手机 AI 协议验证

## 主要实现

- 决策室从“提交问题直接生成”改为本机检索 → 展示候选原文 → 人工勾选 → AI 分析 → 保存分析历史 → 现实复盘。
- 只将勾选的普通知识片段发送到已有云端 /v1/chat；私密日记/加密附件不进入自动检索，也不会自动上传。
- 决策报告要求区分个人材料支持的事实、模型推断、待验证假设，包含方案比较、最强反方、缺失信息与14天最小实验。
- 将决策分析保存在决策条目的 \`meta.decision_analyses\`，最多最近12个版本，不覆盖用户原有预测、观察和行动计划；普通 JSON 备份仍包括决策历史。
- 对模型输出中出现的 \`[k_16位十六进制_序号]\` 引用做本地来源编号核验；未提供的引用显示警告。该核验只验证“指向本机合法片段位置”，不是事实真伪验证。
- 从某次决策报告进入连续追问，携带报告摘要作为预填问题，并限制检索范围为页面明确选择的来源。
- \`AiClient\` 支持注入 HTTP 测试传输层，覆盖手机端 /health 请求头、单轮/多轮消息协议、来源筛选与 401/未配 Key 等异常。
- 本版不要求 Render 新增接口或新增环境变量；但真实多轮问答依赖 Render 部署的后端本身支持 history 字段。

## 不能宣称已经完成的功能

- 未在真实 Android 设备上运行、也未拿到用户的 APP_DEVICE_TOKEN 或 DeepSeek 密钥，因此不能证明“真实手机已能够正常问答”。
- 尚未通过 Render 私有服务的在线身份验证、真实 DeepSeek 计费调用与用户账号端到端联调。
- 本地检索仍为关键词/片段相关性评分，不是完整语义向量 RAG；引用编号核验不代表自动验证每条事实。
- 旧 Preview APK 可能使用不同的签名证书，已有私密日记的旧 App 不应为升级而卸载；正式升级需签名稳定与安全备份验证。
- Render 的私密日记云端访问继续保持关闭；日记及附件只在本机加密阅读。

## 自动化验证

1. 手机客户端 /health、/v1/chat HTTP 请求协议、设备令牌请求头、401 报错、多轮历史、私密日记不进入普通证据。
2. 知识库中真实片段的选择和保存记录；不明来源、伪造来源拒绝视作证据。
3. AI 决策报告持久化、旧决策信息保留、13次分析最多保留最近12次。
4. 原有日记、加密附件、知识分段、知识卡及聊天历史回归。
5. Flutter analyzer、Flutter tests、Android Release APK 编译及 GitHub Release 完整成功。
