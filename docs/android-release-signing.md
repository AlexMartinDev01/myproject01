# 知行罗盘 Android 签名与数据安全清单 (V0.8.2)

## 当前状态

自动化流水线以 `flutter create` 创建 Android 平台目录，并执行 `flutter build apk --release`。尚未配置一份由项目所有者长期持有的独立生产签名密钥。CI 检查 APK 的签名证书与 SHA-256，但**签名校验通过不代表签名是稳定的**。不同构建签名不一致时，Android 不允许直接覆盖安装。不要因升级提示而卸载含有私密日记的旧版。

## 必须完成的正式发布准备

1. 由项目所有者在可信的离线环境生成并备份 Android 上传签名密钥（keystore），独立存放恢复信息。
2. 将 keystore 以 CI Secret（Base64）提供，并把 storePassword、keyPassword、keyAlias 分别保存为秘密；不要提交 keystore、口令或密钥到仓库。
3. 在 Android Gradle release signingConfig 中**仅对具有完整密钥配置的构建**引用生产签名；若缺失，正式发布流水线应失败，而不是生成无法持续升级的 APK。
4. 建立稳定证书 SHA-256 指纹基准；每次发布检查证书指纹、包名、versionCode，并使用此前正式版 APK 测试覆盖安装。
5. 注意：新生产签名无法无损覆盖已经使用另一签名安装的开发预览版。**设置正式签名不是现有数据迁移方案**；必须先实现并验收独立的私密迁移备份/恢复功能。

## 当前普通数据备份范围

普通 JSON 备份包含非私密 entries、持续笔记与版本历史；不包含私密日记、日记附件和云端账号凭据。
V0.8.2 为备份增加 SHA-256 校验值，并在恢复前展示校验状态与记录数量。旧版无校验值的 v1/v2 仍可恢复，但会提示无法验证完整性。

SHA-256 是防损坏的完整性校验，**不是加密或数字签名**，不能抵御能够重新计算哈希的有意篡改者。普通备份仍是可读 JSON，请妥善保管。

## 私密日记限制

日记正文/附件使用本机 AES-256-GCM 加密，加密密钥由手机上的安全存储管理。密钥、SQLite 记录、加密文件三部分共同决定是否能恢复，普通数据备份完全不包含这些数据。重新安装、清除数据、更换设备或改变签名均可能造成私密数据无法恢复。未实现跨设备私密备份前，不要测试卸载迁移，也不要声称可以无损升级。
